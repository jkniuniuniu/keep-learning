## 分库分表
- 数据太大（单表几亿数据 B+Tree 变高 IO 增加）
- 写入扛不住（单机CPU/磁盘达到瓶颈）
- 锁冲突严重（热点数据竞争）

|类型	|含义|
| ------- | ------------ |
|分表	|一库多表|
|分库	|多库|

### 分表
```
user_2023
user_2024
```

### 分库（拆机器）尽量不要分库，很多sql不能用了，复杂度提升太多
```
user_db1
user_db2
```
    - JOIN
    - 外键
    - 本地事务
    - 简单分页

### 分库之后最致命问题
- 本地事务没办法控制了
```
例如：
A库扣钱
B库加钱
如果：
A成功
B失败

数据错乱
```

### 分布式事务
- 强一致性（2PC）（协调机器 等待大家都准备好了 让大家一块儿提交 否则一块儿回滚）
- 最终一致性（现在大多采用这种方式）
```
订单库：
本地事务提交
发MQ消息：
“扣库存”
Step3：
库存系统消费消息
失败：
重试
补偿
```
