### 为什么不能用数组 / 链表 / HashMap
- 磁盘IO非常慢。
```
内存 vs 磁盘
CPU：纳秒级
内存：微秒级
磁盘：毫秒级
数据库真正怕的不是计算
而是磁盘读取次数
```

### 数据库读取数据不是“一条一条读”
```
按页（Page）读取
MySQL InnoDB 默认:16kb 一页
可以理解 磁盘一次IO = 读一个16KB页
什么叫一次IO
一次IO：从磁盘读一个页（page）到内存
比如：我查询用户id=100的数据，我先到内存中去找，没找到，我就要去磁盘去读，我一次只能读取一页（16kb），一页一页的去找
```

### 普通二叉树为什么不行
- 如果100万数据 树会很高 磁盘可能几十次IO
```
1

  2

    3

      4
```

### B树的核心思想
- 一个节点存很多值 而不是 一个节点一个值

### 你可以把它理解成“多叉树”
```
普通二叉树：一个节点最多2个孩子
B+树：一个节点几百上千孩子

举例
[10 20 30 40]
代表
<10
10~20
20~30
30~40
>40
```

### 为什么B+树高度非常低
```
假设
一个页16KB。

一个索引项：20字节

那么：一个节点能存几百个key

假设：一个节点1000个孩子

那么：
高度1
1000条
高度2
100万条

因为：
1000 × 1000
高度3
10亿

所以：
千万级数据，
可能只要3~4次IO。

这就是神的地方。
```
