### 事务的四个隔离级别（从低到高）
1. READ UNCOMMITTED（读未提交）
    - 能读到其他事务未提交的数据
    - 问题：脏读
    ```
    脏读：读到别人未提交的修改，别人回滚了数据就无效。
    ```
    - 几乎不用

2. READ COMMITTED（读已提交）
    - 只能读到其他事务已提交的数据
    - 解决：脏读
    - 问题：不可重复读（同一事务内两次 select 结果不一样）
    ```
    不可重复读：同一事务内，同一条数据被别人改了，两次查询结果不一样。
    ```
    - 很多互联网公司用这个级别（并发高）

3. REPEATABLE READ（可重复读，InnoDB 默认）
    - 同一事务内，多次读取结果完全一致(同一事物 读同一个快照)
    - 解决：脏读、不可重复读
    - 问题：理论上有幻读，但 InnoDB 用 间隙锁 解决了幻读
    ```
    幻读：同一事务内，范围查询多出 / 少了行（插入 / 删除导致）。
    解决：间隙锁 / 临键锁（RR 级别）（如范围查询会出现幻读，间隙锁会把这个范围锁住不让人插入数据）。
    ```
    - 最稳定、最常用

4. SERIALIZABLE（串行化）
    - 完全串行执行，读写互相阻塞
    - 无并发，性能差
    - 极少使用
