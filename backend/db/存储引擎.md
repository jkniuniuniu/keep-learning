### 存储引擎
| 引擎      | 特点           |
| ------- | ------------ |
| InnoDB  | 事务、安全、B+Tree |
| MyISAM  | 老引擎、快但不安全    |
| Memory  | 全内存          |
| Archive | 高压缩归档        |
| CSV     | CSV文件存储      |

### InnoDB（Mysql 目前默认引擎）
- 支持事务（要么全部成功 要么全部回滚）
- 支持 MVCC（读写并发：例如有人写数据，别人还能读数据，不容易锁死）
- 行锁（Row Lock）（锁一行，而不是锁整张表，高并发性能强很多）
- 聚簇索引
- 崩溃恢复（Redo Log Undo Log，支持断电后的数据回复，企业级安全）
- 支持外键、主键、自增

### MyISAM（Mysql 老引擎）
- 优点查询快（数据结构简单）（结构简单的意思就是阉割版本，不像innoBD做版本控制 做崩溃恢复 做索引等等东西）
- 不支持事务、不支持行锁，只有表级锁（一写全表锁住）
- 读写分离：查询极快，写入阻塞严重
- 不支持崩溃安全恢复，断电易丢数据 / 损坏表
- 不支持外键

### Memory（内存引擎） - 小众
- 数据完全存在内存，速度极快，断电数据全部清空
- 不支持事务、仅表锁
- 用途：临时计算、临时缓存、高频临时查询

### Archive 归档引擎 - 小众
- 只支持插入、查询，不支持修改、删除、索引
- 压缩率高，占用空间极小
- 用途：海量日志、归档数据、只存不更的流水记录

### CSV 引擎 - 小众
- 数据以 CSV 文本存储，可直接用 Excel 打开
- 无索引、性能差
- 用途：简单数据导入导出、外部文件对接

## 总结
- 新项目 100% 用 InnoDB，这是行业标准
- 需要事务、转账、订单、库存 → 必选 InnoDB
- 只有纯查询、万年不改的历史数据 → 才考虑 MyISAM
- 临时数据、高速临时计算 → 用 Memory
