## 为什么有树这个东西
```
数组的问题：查找慢 插入慢2
链表的问题：查找更慢1
```

## 二叉树
- 每个节点有0-2个叶子
```
        A
       / \
      B   C
```
- 树高度很重要，查找通常是从上往下，高度越高查找越慢
```
        A       第1层
       / \
      B   C     第2层
     / \
    D   E       第3层
```

### 前序遍历
```
// 根 -> 左 -> 右
      A
     / \
    B   C

A B C
```

### 中序遍历（极其重要）
```
// 左 -> 根 -> 右
      A
     / \
    B   C

B A C
```

### 后序遍历（删除比较重要，删除是从子删到父）
```
// 左 -> 右 -> 根
      A
     / \
    B   C

B C A
```

## 二叉搜索树（BST）
### BST核心规则
```
左边都比它小
右边都比它大
        8
       / \
      3   10
     / \    \
    1   6    14
```

### BST最大的问题
```
不保证平衡
1
 \
  2
   \
    3
这不就变成链表了么
```

## AVL树（平衡二叉树）

### 解决的问题非常直接
- BST 会歪
```
1
 \
  2
   \
    3
遇到这种情况会旋转
    2
   / \
  1   3
```

### AVL问题
- 太追求平衡，数据量大的情况下 插入和删除需要旋转很多（旋转代价高）

### AVL适合什么场景
- 查找远多于修改的

## 红黑树（TreeMap TreeSet HashMap(JDK8+ 链表长度 > 8 树化) 底层全是）

### 红黑树核心规则
- 根节点必须黑色 
- 红节点不能连续
- 从任意节点到叶子,黑节点数量必须相同
```
       10(B)
      /     \
   5(R)    20(R)

   颜色只是辅助 便于数据的维护 查找实际还是靠二分 左大右小的逻辑
   所以这个红黑的作用只是用规则来放宽左右的平衡条件，让它不那么严格，只有颜色规则不符合的情况下才会去旋转
```
